# Changes worth back-porting to Calycopis-broker.
#[root@lithosia-dsh-pod]

    1. A Markdown / HTML header format, which upstream is missing.

        Upstream licence-header.mdc documents Python/#, Java and XML, and
        upstream ai-metrics.mdc documents Java, Python/# and XML - but
        neither covers Markdown, even though Calycopis-broker's own
        AGENTS.md already carries an HTML comment header. The Markdown
        template below closes that gap, so the written rule matches what
        the project already does.

    2. An exemption for dotfiles, lockfiles and generated files.

        Upstream requires a header on "every file you create or modify",
        with no exemption at all. That contradicts upstream's own
        agents/rules/*.mdc files, which carry no header, and it would also
        demand a GPL block inside .gitignore.

    3. ai-metrics should state the exemption at the top.

        The upstream rule asserts "every file" in its first paragraph, so
        the exemption belongs there as well as in licence-header.mdc.

    4. The AGENTS.md "Coding rules" section.

        Upstream lists the rules as bullets inside "Coding conventions". A
        separate section, with a rule/requirement table plus the exemption
        summary, is easier to follow, and it is the natural place to
        document where the name/version/model values come from.

    5. One AIMetrics entry per change, not per edit.

        Upstream records one entry per modification, with a timestamp, and
        says nothing about a run of edits made as part of a single change.
        A short burst of edits then produces a column of near-identical
        entries, which records keystrokes rather than contribution. The
        rule groups such a run into one entry using an ISO 8601 interval,
        from the first edit to the last, and issue bodies follow the same
        rule rather than always using a timestamp. Applied here in d39d6c8;
        the text is in part 5 below.

# Text to apply, part 1. The "Exempt files" section for licence-header.mdc.
#[root@lithosia-dsh-pod]

    Add after the existing "Rules:" list, and drop any narrower note about
    agents/rules/*.mdc being exempt:

        ### Exempt files

        A licence header asserts copyright over the project's authored work.
        Files that are not authored work, or that a tool owns, carry no header:

        - **Dotfiles** - any file whose name begins with `.`, at any level.
          For example `.gitignore`, `.gitattributes`, `.editorconfig`, `.env`,
          `.dockerignore`.
        - **Lockfiles and machine-generated files** - for example
          `pnpm-lock.yaml` or `package-lock.json`, which are regenerated by
          their tool rather than written.
        - **`agents/rules/*.mdc`** - imported configuration, kept in the form
          it has upstream in the Calycopis-broker project.

        Hand-authored configuration is **not** exempt: YAML, JSON, XML,
        Dockerfiles and shell scripts are project source and get a header,
        using the matching template above. A workflow file such as
        `.github/workflows/ci.yml` is authored work and gets one too - it is
        configuration with a `#` template, not a dotfile.

    Written with em-dashes in the real file; plain hyphens are used here so
    the note survives being read as plain text.

# Text to apply, part 4. The AGENTS.md "Coding rules" section.
#[root@lithosia-dsh-pod]

    A separate section, in place of (or ahead of) the rule bullets in
    "Coding conventions":

        ## Coding rules

        The rules in [`agents/rules/`](agents/rules/) apply to every file an
        agent creates or modifies, and to every agent commit message.

        | Rule | Requirement |
        |---|---|
        | [`licence-header.mdc`](agents/rules/licence-header.mdc) | Every new source file starts with the GPL `<meta:header>` block, using the comment syntax for its language and the project's copyright line. |
        | [`copyright-year.mdc`](agents/rules/copyright-year.mdc) | When a file carrying a `<meta:licence>` block is modified, bump its `Copyright (C) YYYY` to the current year. |
        | [`ai-metrics.mdc`](agents/rules/ai-metrics.mdc) | One `AIMetrics` entry per **change**, not per edit, appended to a file header rather than replacing existing entries: `timestamp` for a change made in one pass, or `interval` covering it when several edits were made in sequence. Every agent commit message ends with one using `interval`, and so does every GitHub issue an agent creates, in a fenced code block. |
        | [`unexpected-behaviour.mdc`](agents/rules/unexpected-behaviour.mdc) | Stop and ask before coding around unexpected behaviour from an API, service or component. |

        Headers are not required on files that are not authored work:

        - **dotfiles** - a file whose name begins with `.`, anywhere in the tree
          (`.gitignore`, `.gitattributes`, `.editorconfig`, `.env`);
        - **lockfiles and machine-generated files** - regenerated by their tool
          rather than written (`pnpm-lock.yaml`, `package-lock.json`);
        - **`agents/rules/*.mdc`** - imported configuration.

        Hand-authored configuration is not exempt: YAML, JSON, XML, Dockerfiles
        and shell scripts are source and get a header.

# Text to apply, part 5. One entry per change, for ai-metrics.mdc.
#[root@lithosia-dsh-pod]

    Replace the "Each entry records one agent/model contribution to the
    file:" lead-in and the timestamp bullet that follows it:

        Each entry records one agent/model contribution to the file. Log one
        entry per **change**, not one per edit: a change made through several
        edits in sequence is a single contribution.

        - `timestamp` - for a change made in one pass: the date and time of the
          modification, ISO 8601 format (YYYY-MM-DDThh:mm:ss).
        - `interval` - for a change made through several edits in sequence: an
          ISO 8601 interval covering them, from the first edit to the last (e.g.
          `2026-02-14T15:30:00/2026-02-14T15:52:00`). Use this instead of
          `timestamp` rather than adding an entry per edit, which turns a record
          of who contributed what into a log of keystrokes. Commit messages
          always use `interval`, because a commit summarises a session's work.

    Add ahead of the first format block:

        In every format below, substitute `interval` for `timestamp` when the
        change spanned several edits in sequence.

    Replace the issue-body bullet that requires a timestamp:

        - Use `timestamp` for a change made in one pass, or `interval` when the
          issue was written or revised through several edits in sequence - one
          entry covering them, exactly as for a file header. (A commit message
          always uses `interval`, because a commit summarises a session's work.)
          Append a new entry for a later change rather than replacing existing
          ones.

    Plain hyphens where the real file has em-dashes, as in part 1.
